# MightPulse Probe 実装候補台帳

更新日：2026-10-14  
対象ブランチ：`feat/mightpulse-probe-expansion-2026-10-14`

## 運用ルール

- Probeで実際に観測できた情報だけを候補として記録する。未取得フィールドを推測で追加しない。
- API仕様の根拠と実測レスポンスを分けて記録する。既存EagleEyeコードに呼び出しがあることだけで「公式仕様」と断定しない。
- 新しい候補は本番コードへ自動反映しない。
- 本番保存の可否は、既存の正規保存処理・ID整合性・レスポンス形状を確認した後に人が判断する。
- APIキー、Authorization、token、secret、passwordなどの秘密値や個人情報をサンプルとして記録しない。サンプルはマスクまたは型だけにする。
- 生レスポンスはR2のProbe実行記録、索引・実装判断はこの台帳に分け、D1に大きなレスポンスを複製しない。

## ステータス

| ステータス | 意味 |
|---|---|
| `UNOBSERVED` | 候補名のみ。レスポンス未観測 |
| `OBSERVED` | Probeで実際のフィールドを観測済み |
| `MAPPING_REVIEW` | 既存EagleEyeの保存先・利用箇所を調査中 |
| `APPROVED` | 根拠と保存条件を確認し、本番反映を承認 |
| `IMPLEMENTED` | 正規処理へ実装済み、テスト済み |
| `REJECTED` | 重複・不適切・根拠不足などで採用しない |

## 既存コマンドとの照合メモ

- `src/mightpulse-probe.js` の `MIGHTPULSE_PROBE_COMMANDS` がProbeの実行台帳。
- `category: "EagleEye Retrieval"` は既存EagleEye内部の取得・更新経路を示す分類であり、公式APIコマンドの分類とは分けて扱う。
- `/kvk/matchups` は既存EagleEyeのMighty判定処理でも使用されている。これは既存コード上の使用根拠であり、公開API仕様書の確認とは別扱い。
- プレイヤー情報の本番保存は、レスポンス内に明示的なプレイヤーIDが存在し、リクエスト対象と整合するときのみ候補にする。
- ランキングの本番保存は、許可リストにあるランキングボードと有効な対象王国が確認できるときのみ候補にする。
